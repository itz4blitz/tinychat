Contributing

From a typo to a network adapter. Talk it through on Discord, or follow CONTRIBUTING.md. This page is the short version.

Roadmap

The goal is a client as full as Slack, Discord, Telegram, Teams, Signal and Android Messages, that stays small and fast. These five increments are what is underway. Each one is usable on its own. Discord and Slack came first, because they signed in first. Signal is partial: photos and files are named, not shown. Messages shows photos, names other files, and sends reactions. Calls stay on the phone.

IncrementDone whenWhere it stands
1. Looks real A normal conversation reads here: avatars, names, images, files, links, formatting, mentions, emoji, edits, deletions, reactions, scrollback, a multi-line composer. In, on Discord, Slack, Teams and Telegram. On Signal a photo or file is a labelled line, not the file.
2. Everything and everyone Every server, channel and group is listed. People, presence, typing, starting a DM, the quick switcher, unread, mentions and mutes are right. A DM or mention notifies, and the Dock badge matches. The lists, people, presence, typing, unread and mutes are in. Notifications and the Dock badge are not.
3. Answer in kind Threads, reactions, reply, edit, delete, paste, attach, mention completion, the emoji picker, and message search. Nobody can tell which client sent it. All of that is in the window except message search. tinyclient --text --search searches cached message text. The switcher finds a conversation, a person or a server. Opening a hit in the window, and searching the network, are not built.
4. Talk A call in mediad, which runs only while the call does. Discord voice first, then one screen share each way. Slack huddles after a spike that is heard on a real huddle. Telegram 1:1 calls. Teams calls and meetings open in Teams. Discord voice is in, including its end-to-end encryption. Video, screen share, Slack huddles and Telegram calls are not. Their buttons open the official app.
5. Every network Telegram, then Teams chat, at the level of increments 1 to 3, then Signal and Android Messages. Teams meetings open in Teams until the native join ships. A work or school Teams account can still be blocked by the tenant, and nothing here changes that. Telegram and Teams chat are in at that level, except search and notifications. Signal sends and receives text; its photos and files are a labelled line. Messages shows photos, names other files, and sends reactions. Teams personal accounts are not built.

What is not built yet opens in the official app, on the exact item. That includes admin, moderation, bot buttons, app platforms, canvases, a video gallery, and Teams meetings. Those are part of the goal. Each one ships when it can pass the same memory, speed, and idle budgets. The line is in docs/product/01-persona-scope.md.

Where help is needed

Say which area you want on Discord, and it is yours until it ships or you hand it back. One area at a time.

The product documents are the spec. Read the one named for your area before you write code. Where a document still leaves a choice open, propose the answer in Discord. Once there is general agreement, the decision goes into that document in the same change as the code. A bug report with the redacted log counts, and so does testing an area someone else owns, on a real account, on Linux or on Windows.

The order below is the order we would build them. A later row is still open if that is the one you want.

AreaDone whenSpec

Start here

git clone https://github.com/itz4blitz/tinyclient
cd tinyclient
cargo test --workspace
TINYCLIENT_DIR=/tmp/tinyclient-demo cargo run -p chatd -- --seed-demo=live
TINYCLIENT_DIR=/tmp/tinyclient-demo cargo run -p tinyclient --features gui

Work against the demo or the tests’ local fakes. Run chatd with TINYCLIENT_DIR set while developing, so a half-finished change never touches your real sessions or cache. Build from source lists the prerequisites.

What a change must keep true

  • Budgets. A feature is done when it passes its memory, speed and idle budget, measured from outside the process.
  • Process boundaries. chatd never decodes media; mediad never runs without a call; the window never talks to a network.
  • Nothing automated, and nothing sent that the user did not ask for.
  • Protocol additions are optional fields, so an older frame still reads.
  • No new async runtime and no second TLS stack in chatd without a measured reason.
